# 知识建模与组织

EasyRAG 把知识保存为可编辑的原文，把原文切成可定位的片段，再从片段生成检索索引。组织方式服务于两个目标：找得到与问题有关的内容，回答后还能核对当时引用了什么。

本文面向首次了解项目的技术评审。阅读后应能解释原文、切片和索引为何分开，判断资料更新或出处异常发生在哪一层。模块全貌见[架构设计](架构设计.md)，检索排序见[检索链路与改进](检索链路与改进.md)。

## 一、资料是事实，切片是证据单元，索引是派生数据

| 对象 | 保存什么 | 为什么单独存在 |
|---|---|---|
| document | 完整正文、标题、来源文件名、标签、内容哈希和索引状态 | 编辑、删除和重建都必须有确定的原文依据 |
| chunk | 原文子串、所属资料、顺序、标题路径、UTF-8 字节范围和 token 数 | 小片段适合检索，字节范围把证据连回原文 |
| Chroma 索引 | 代表片段的向量、正文与元数据，以 chunk ID 标识 | 执行语义检索，可从 MySQL 重建 |
| BM25 缓存 | Chroma 载荷的分词结果与词法评分结构 | 补充精确术语匹配，随索引重建，不另存业务事实 |
| 问答历史 | 完成时的问题、答案、来源正文和流程快照 | 保留过去回答的依据，不随资料修改而改写 |

MySQL 由资料模块 A 独占，原文、全部切片和问答历史以它为准；索引模块 B 不反向读取数据库。应用编排 G 取得 A 的快照，调用 B 切片和索引，再核对双方数据。这使正常收录与故障重建使用同一组数据契约，具体见[资料管理](子Issue-A-资料管理.md)与[应用编排](子Issue-G-应用编排.md)。

向量库因此不承担“唯一原件”的职责。embedding 模型更换、索引损坏或切片参数调整时，可以依据原文重新计算，不必从向量载荷猜测用户保存过什么。代价是要维护数据库与索引的一致性，不能只看两个系统都能连接就开放问答。

## 二、先利用已有结构，再考虑更复杂的组织

### 收录不要求用户先整理标签

当前上传 UTF-8 的 Markdown 或纯文本，单篇上限为 1 MiB。标题依次取非空 `frontmatter.title`、正文首个一级标题、去扩展名的文件名；标签只解析可选 frontmatter 中的数组或块列表。没有 frontmatter 仍可收录和问答。

这些元数据的用途需要分开理解：

| 字段 | 当前用途 | 不代表什么 |
|---|---|---|
| `title` | 资料展示、列表标题搜索、出处识别 | 不会额外拼到每个片段的 embedding 输入 |
| `heading_path` | 表达片段所属 Markdown 小节，进入向量输入和 BM25 语料 | 不是人工分类，也不补齐原文缺少的知识 |
| `tags` | 保存、展示并随索引元数据传递 | 不参与检索过滤、查询扩展或排序 |
| `source_uri` | 保存去掉目录部分的原始文件名 | 不承担网页抓取或目录同步 |

原文保留 frontmatter，所以其中出现的词仍可能作为正文被检索；“tags 不参与检索”指没有独立的标签检索规则。用户在正文中保存 HTTP(S) 链接后可点击打开，系统不会读取链接指向的网页，链接地址也不等于已收录网页内容。

当前不建立分类树、自动关键词或 LLM 生成的知识摘要层。标题和正文已有足够直接的结构信号，额外生成元数据会增加写入成本和另一套需要维护的解释。是否引入分类应由整理、浏览或明确限定范围的需求决定，不能先假设它必然改善问答。

### 切片保留结构，也约束模型输入

切片先识别一至三级 Markdown 标题，再将超容量小节按段落、句子、Unicode 码点逐级拆开。相邻小块在容量允许时合并；跨小节合并只保留共同标题路径。代码栅栏内的 `#`、空行和标点不作结构边界，过长代码块仍可能被硬切。

默认上限是 512 token、合并目标是 64 token。512 限制的是“正文 + 非空标题路径 + 模型特殊 token”的完整输入；64 是软目标，不能为凑长度突破上限。正文另受数据库单片字节上限约束。这里使用真实 tokenizer 计数，不能用中文字符数近似替代。

标题路径随正文进入 embedding，能给被拆开的局部内容增加小节语义；它也消耗预算，泛化的标题还可能稀释正文信号。当前选择保留，尚未用单独的开关对照证明所有语料都受益。细节和测试边界见[索引管线](子Issue-B-索引管线.md)。

不采用整篇直接检索，是为了避免长文主题混杂、证据过大；不只按固定字符数切分，是为了减少定义与解释、代码与所属章节被任意分开。现有方案仍会拆开长段落，且没有父子片段回填或邻接片段自动扩展，相关片段并不必然包含完整答案。

## 三、一个片段如何既参与检索，又能回到原文

样例资料中的 OS Buffer 短卡在“详细 / 重点”下写有：数据写入缓冲区即返回成功，后台异步落盘，因此断电可能丢失；还列出 `sync`、`fsync`、`fdatasync`。这段内容同时支持“写成功为何仍会丢失”和“如何强制落盘”的问题。

其处理过程可以按四个对象核对：

1. document 保存完整短卡，frontmatter、换行和正文都在其中。
2. chunk 保存某个精确原文范围及标题路径；范围外的标题上下文不被伪装成正文。
3. 索引用 `text + 换行 + heading_path` 生成向量，BM25 对同样的文本分词；载荷正文仍是原文子串。
4. 检索返回 chunk ID，G 用它向 A 取得出处与原文位置；问答中的 `[n]` 是本次检索排名，不是数据库 ID。

该例在 [Q21 的混合检索报告](eval/retrieval-v2-hybrid-2026-09-22.md)中有具体命中记录。短卡结构让它可被检索、可定位，但能否进入前几名还取决于排序：它曾被同主题长篇压出候选，不能把结构化存储本身当成召回保证。

### 原文位置必须与正文属于同一版本

`byte_start` 和 `byte_end` 是完整原文 UTF-8 编码后的左闭右开范围。系统要求：

```text
chunk.text = decode_utf8(utf8(document.content)[byte_start:byte_end])
```

范围不能切开多字节字符，片段不得重叠，所有非空白字符必须被覆盖；首尾或片间允许纯空白间隙。偏移在切分时从原文位置计算，不能用正文字符串搜索补算，否则同一段话重复出现时可能定位到错误位置。

内容哈希用于判断是否需要重索引：先统一换行、去掉约定的首尾空白，再计算 SHA-256。它不是原文版本号。仅换行或首尾空白变化可能得到相同哈希，却改变字节位置；因此同哈希更新只触碰更新时间，保留旧正文、元数据和切片，不能把格式不同的新正文搭配旧偏移保存。

## 四、重复内容与更新如何影响知识组织

### 保留全部原文，只对索引代表去重

同一资料中 embedding 输入完全相同的片段，只把第一次出现的片段放入索引；MySQL 仍保留全部切片。跨资料的相同内容分别保留，因为它们有各自的来源和生命周期。内容哈希因此不设跨资料唯一约束。

这一选择来自重复内容压测：大量相同向量会影响 HNSW 导航，即使精确余弦能区分正确片段，近似检索也可能漏掉它。实验与选择依据见[索引管线的 B-15 论述](子Issue-B-索引管线.md#b-15为什么在索引层去重)。

在切片层去重会丢掉原文覆盖；跨资料去重会混淆出处。索引层去重保留了这两个不变量，代价是重复段落的检索引用定位到第一次出现处。MySQL 的切片数与向量数可以不同，恢复核验必须应用同一代表规则，不能要求两边数量相等。

### 资料变更先保证新旧证据不混用

| 操作 | 当前行为 | 对回答的影响 |
|---|---|---|
| 上传 | 先入库为 PENDING，后台切片、索引，成功后 INDEXED | 列表可见不等于已可检索 |
| 正文变更或手动重索引 | 持变更许可，撤旧索引、更新资料或状态，再重建 | 在变更完成前不让问答读到半套数据 |
| 删除 | 先删除派生索引，再软删资料并清除切片 | 后续提问不再检索该资料 |
| 索引失败 | 记录失败；无法确认清理或终态时要求恢复 | 不以“部分写入成功”继续服务 |
| 查看历史 | 读取回答完成时的来源快照 | 不会将旧引用重新解释为修改后的正文 |

一致性检查不仅数记录，还核对 ID、所属资料、索引顺序、正文与元数据。启动后的就绪确认和停服重建负责把这种不变量重新建立起来。当前以单进程、串行索引和问答/变更许可控制复杂度，耗时索引会影响问答可用性；没有跨存储的原子事务。

## 五、边界与排查入口

遇到“资料明明存在，回答却没有用到”时，先检查对象所在层，而不是直接更换模型：

| 现象 | 先核对什么 | 对应边界 |
|---|---|---|
| 上传后列表可见，但尚无检索结果 | 索引状态与失败原因，正文是否已生成切片 | A 的资料状态、G 的索引流程 |
| 关键文字不在任何切片 | 原文覆盖、代码栅栏、容量拆分与字节范围 | B 切片，A 存储契约 |
| 切片存在，目标来源未进候选 | 索引一致性、两个召回通道与融合排名 | B 检索；见[检索排查](检索链路与改进.md) |
| 命中了，但未进入回答 | `relevant` 选择、回答覆盖和正文引用 | C 工作流；见[问答边界](问答工作流与边界.md) |
| 原文跳转不符或历史看起来过时 | 当前来源与历史快照是否混淆，偏移是否同版本 | A 出处与历史、G 的核对 |

当前资料模型没有知识图谱、父子分段或分类树。列表虽能查询资料记录，问答入口尚未接入数据库统计和完整目录；几个命中片段不能证明全库数量、完整资料清单或主题覆盖情况。局部检索评估的适用范围见[评估检索质量](评估检索质量.md)。
