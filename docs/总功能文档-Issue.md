## 一、背景

收藏 ≠ 拥有：资料越攒越多、散落各处，无法检索与调用。本项目做一个能管理和调用知识的系统——随手丢进去，用一句话问出来，答案附出处。

## 二、用户画像

目标用户：**有持续记笔记、存资料习惯的个人**——学生、开发者、研究者。

| 维度 | 基线假设（必须支持） | 增强场景（有则更好） |
|---|---|---|
| 资料形态 | 普通 markdown 笔记、纯文本、网页链接 | 带 frontmatter 的结构化笔记 |
| 组织方式 | 正文有标题层级，目录结构随意 | 目录分类清晰、已有标签体系 |
| 使用工具 | 任意编辑器 | Obsidian / Typora / VS Code |
| 规模 | 几十到几百篇 | —— |

**明确不假设**：不假设用户使用 Obsidian、不假设写 frontmatter、不假设文件命名与目录规整。核心链路只依赖普遍存在的结构信号（文档标题、Markdown 标题层级）；frontmatter 的 `tags` 属于可选增强，缺失时功能完整、只是少一个过滤维度。

**不为谁设计**：团队与企业的多人协作场景（无权限体系）、以 PDF / Word 文献库为主的用户（不做富格式解析）、需要在系统内写作的用户（不做编辑器）。

## 三、产品定义

一个网页，三件事：

1. **收录与管理资料**：md / txt / 链接，支持更新与删除
2. **问答**：一句话提问 → 答案 + 可点开的出处（定位到文档与位置）
3. **更新同步**：资料更新或删除后，问答结果随之更新

拒答是一等行为：检索质量不足时返回"库里没有"，不进入生成。

## 四、功能边界

### 做（范围内）

- 资料收录（md / txt / URL）、列表、更新、删除
- 切片、embedding、检索、agent 多步检索
- 带出处的问答、拒答
- 黄金问答集与评估（hit@k / 拒答正确率）
- 检索过程展示（重查次数、采用/丢弃的片段）
- 独立问答历史：持久保存回答与当时出处、分页查看、删除、按当前资料重新提问；不自动作为后续上下文
- 流式输出：按 M4 后续步骤验证首字与完整耗时，完成后校验引用并保存历史

### 不做（范围外）

| 项 | 理由 |
|---|---|
| 资料编辑器 / 阅读器 | 编辑发生在本地工具，系统只收录与管理 |
| 登录、多用户、权限 | 单用户工具 |
| PDF / Word 富格式解析 | 主知识形态为 md 与网页；解析工程量大、不增加检索深度（后续可作扩展） |
| Obsidian 插件形态 | 网页形态覆盖不依赖 Obsidian 的用户；RAG 服务独立于 UI 形态，插件可作为后续第二客户端接入同一套 API |

### 已定（原待定项的裁决）

- **收录入口形态：网页上传优先**。理由：网页形态覆盖面广（不依赖用户使用 Obsidian）；后续可向 Obsidian 插件方向演化——RAG 服务独立于 UI 形态，插件可作为第二客户端接入同一套 API。文件夹同步（以文件夹为真相源）暂不做，数据模型以 `source` 字段预留，实施遇阻或需要贴近本地知识库使用习惯时再启用。

## 五、模块划分（各对应一个子 Issue）

| 模块 | 位置 | 职责 |
|---|---|---|
| **A 资料管理** | Python knowledge | 资料/切片、输入规则、MySQL 短事务与文档状态；唯一业务表写入者 |
| **B 检索索引** | Python retrieval | 切片、embedding、Chroma 维护与检索；不访问 MySQL |
| **C 问答 Agent** | Python qa | 使用注入的检索/模型接口完成判断、生成、拒答和 trace；不访问存储 |
| **D 评估** | 离线 CLI | 维护现有黄金集、跑集、指标和报告；不进入线上依赖链 |
| **E 前端** | Vue | 收录/管理界面、问答界面（答案 + 出处 + 检索过程） |
| **F 回答模型** | Python answer_models | 配置文件、密钥边界、地址解析和模型会话 |
| **G 应用接入** | FastAPI application | HTTP、用例编排、门禁、单执行者、恢复、健康检查与 CLI |

模块间通信：**前端 ↔ FastAPI（REST）**；G 通过 A/B/C/F 的公开 Python 接口调用。四个业务模块互不引用，C 的检索和模型接口由 G 注入；不传递数据库连接、索引对象或 SDK 客户端。

写入流由 G 安排：A 保存原文 → B 切片 → A 落库生成 chunk ID → B embedding 与索引替换 → A 确认终态。G 持有跨步骤的变更许可；A/B 分别负责自身事务和清理。

## 七、架构不变量

1. **MySQL 是资料、切片与已完成问答历史的唯一真相源**，且只有 A 写入。模型配置由 F 管理本机文件；现有黄金集和离线评估报告由 D 管理文件。问答 trace 随响应返回，并与当时来源一起保存在历史快照中；技术失败不保存为已完成记录。
2. **派生索引可重建**：向量与词法索引按 chunk_id 关联 MySQL，丢失即重算，不构成事故。
3. **溯源链路贯穿全程**：chunk_id 从索引带到 API 响应，中途不丢。
4. **拒答是一等行为**：检索质量不足时不进入生成。
