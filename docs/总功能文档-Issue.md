# 总功能文档：EasyRAG 个人知识库问答系统

对应 [总 Issue #1](https://github.com/epoch-fresh-2026/EasyRAG/issues/1)。本文定义当前产品范围、模块协作和用户故事；技术边界见 [架构设计](架构设计.md)，请求响应见 [API 文档](api.md)。

## 一、背景与用户

个人笔记和收藏越来越多，真正需要时却很难找到。EasyRAG 面向有记录习惯的个人，让资料能通过问题被调用，同时能核验回答依据。

不要求使用 Obsidian，不要求给每篇笔记写 frontmatter 或标签。核心链路使用正文、文档标题和 Markdown 标题层级；可选元数据不应成为使用门槛。

## 二、当前功能

- **资料管理**：上传单份 Markdown/TXT，按标题搜索、状态筛选和分页浏览；预览、编辑、删除及手动重索引。正文中的 HTTP(S) 链接可点击打开，外部网页不会自动抓取或入库。
- **知识问答**：混合检索、证据充分性判定、相关片段筛选、生成或拒答、引用编号校验。提供流式显示和可打开的原文出处。
- **更新同步**：更新索引完成后，新问答使用当前资料；删除后不再检索该资料。未确认索引一致时暂停问答，避免混用新旧数据。检索到新片段不保证模型回答正确。
- **问答历史**：保存完成的回答、部分回答和拒答，包含模型、耗时、检索过程与当时来源；支持分页、删除和重新提问。历史不自动作为下一问上下文。
- **回答模型**：网页配置 OpenAI 兼容接口、DeepSeek 或使用兼容接口的本地 Ollama；每问冻结配置，切换回答模型不重建索引。
- **评估**：通过 CLI 运行黄金集，读取召回、回答、拒答、引用与延迟报告。

## 三、范围与取舍

| 选择 | 理由和边界 |
|---|---|
| 网页上传 md/txt | 覆盖常见笔记，不要求特定笔记工具；暂不做文件夹同步或多文件批量上传 |
| 正文承载链接 | 可随笔记保存和打开；不等于独立链接管理或网页正文收录。网页收录暂不考虑，未来若实现须独立于资料库且不参与检索 |
| 文档与标题层级组织知识 | 保留用户原文结构；标签可选，仅作展示，不作为检索前提 |
| 单用户、单后端进程 | 集中管理一致性与资源；不提供登录、多用户权限或分布式部署 |
| Markdown 预览与纯文本编辑 | 满足资料核验及修改；不实现富文本编辑器或 PDF/Word 解析 |
| 评估保留为 CLI 和报告 | 便于隔离语料、控制模型调用并复现结果；不建设网页评估看板 |

## 六、一致性与回答约束

1. MySQL 保存资料、切片与完成的问答历史，由 A 独占；F 独占模型配置文件，D 管理题集和报告。
2. 索引是可重建的派生数据。更新和删除由 G 持变更许可协调；无法确认清理及终态时暂停问答并要求恢复。失败资料已确认清除索引并记为 FAILED 时可重新开放问答。恢复按去重后的连续序号核对向量，SQL 保留原始切片顺序。
3. `chunk_id` 贯穿索引、问答和出处。正文定位统一为 UTF-8 字节范围，历史保存回答时的来源快照。
4. 无候选或判定 NONE 时直接拒答，不调用生成；技术错误不伪装成拒答，也不保存成完成历史。
5. 流式完成事件必须在引用校验及历史保存成功后发送。提交阶段断连可能已保存记录，客户端不会自动重试。

这些约束不等于答案的语义保证。编号合法只能证明所引片段存在于允许集合；模型可能选错主题、夸大覆盖或写出片段没有的事实。历史快照保留当时的依据，也会保留当时的错误答案。

## 八、当前阶段与后续方向

基础管理、更新同步、混合检索、回答约束、流式输出、历史、模型配置和 CLI 评估已交付。M5 收尾限定为检索过程可见性与文档一致性，不包含评估看板；U7 的发布状态见上表。

问答依赖局部检索证据，尚未使用数据库统计和完整目录作为上下文。全库数量、完整清单、全库概览不属于当前保证范围；有效引用不保证回答对象正确，既有黄金集不能证明这类全局问题的正确性。

V2 已延期。若重启，可研究让确定的统计与目录事实作为上下文交给 LLM 汇总回答，并比较有限工具选择与受限 agent 的效果。分类树可辅助浏览和限定范围，但不是统计能力的必需前置条件。以上尚未实现，不在当前版本追加分类器、工具协议或新接口。

## 九、协作与验收

每个功能通过小 PR 关联总 Issue 和对应模块 Issue，说明做了什么及原因。代码规则用模块/应用测试验证，存储与恢复用隔离 MySQL 集成测试验证，前端用交互和布局测试验证；检索改进附样本、配置及前后评估结果。历史设计过程通过 Issue、PR 和 Git 记录追溯。

## 十、已知缺口与验收条件

实现存在、测试通过与用户任务完成需要分别提供证据。当前待补验收见 [#93](https://github.com/epoch-fresh-2026/EasyRAG/issues/93)。

| 当前限制 | 验收需要的证据 |
|---|---|
| 引用编号校验不检查事实真伪，模型仍可能误判覆盖或答错主体 | 分开核对出处可定位、逐项事实支持与回答覆盖；人工复核成功回答、部分回答和拒答，不以 ANSWERED 状态代替正确性 |
| v1/v2/v3 共用 29 篇样例，已参与调试；模型判官未经人工校准 | 冻结实现、配置及指标后，使用未参与调试的资料和预先人工标注的问题验收；保留成功、失败、未完成样本和判官误判 |
| 测试和 PR 合入只能证明对应源码与测试环境，不能证明运行中的服务已更新 | 按部署版本验证上传、修改、删除后的新问答与历史快照；确认恢复门禁、失败及取消的终态，记录模型配置和数据范围 |

恢复序号、繁忙上传、元话语漏检、重试漏计已分别由 [#89](https://github.com/epoch-fresh-2026/EasyRAG/issues/89)、[#90](https://github.com/epoch-fresh-2026/EasyRAG/issues/90)、[#91](https://github.com/epoch-fresh-2026/EasyRAG/issues/91)、[#92](https://github.com/epoch-fresh-2026/EasyRAG/issues/92) 修复并合入；复现与测试证据保留在对应 Issue/PR。评估使用 `cited_sentence_support_v2` 与 `retry_accounting_v2`，历史报告保留当时口径，详见[评估说明](评估检索质量.md)。

核心验收围绕用户结果进行：上传后能检索；修改、删除后新问答依据随之变化，旧历史仍能核验；缺少证据时分流和回答符合预先标注的边界；失败与取消有明确终态。模块数量、接口数量和测试总数不能替代这些证据。
