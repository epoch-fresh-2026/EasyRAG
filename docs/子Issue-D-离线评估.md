# 子 Issue D：检索与问答评估

Issue：[#37](https://github.com/vansye/EasyRAG/issues/37)，父 Issue：#1。架构：[模块与数据流](架构设计.md)。D 维护离线召回与在线问答评估，不建设评估数据库或网页看板。

## 功能与数据原型

用户运行现有黄金集，获得可复现的召回指标和报告。D 独占样例选择、题集解析、指标口径及报告生成；不参与线上索引或问答许可。

```python
Question = {id, category, question, expected_sources}
EvaluationInput = {corpus_path, questions_path, model, chunk_parameters}
EvaluationResult = {rankings, hit_at_k, metrics_by_category, timings}
evaluate(input: EvaluationInput) -> EvaluationResult
render_report(result: EvaluationResult) -> str
```

## 接口与边界

- `python -m scripts.eval_retrieval`：以隔离样例索引运行召回评估，报告 hit@1/3/5/10；N/P 类不进入该分母。
- `python -m scripts.eval_answers`：运行实际判定与生成，输出回答、拒答、错源、耗时与调用次数；`--faithfulness` 增加逐句引用支持核对。
- `python -m scripts.export_history_failures`：只读导出 REFUSED/PARTIAL 历史供人工标注；运行产物留在被 Git 忽略的本地目录。
- CLI 通过 B/C/F 的公开入口复用能力，评估建立隔离索引，不修改业务 MySQL、Chroma、模型配置或问答历史。
- 前后对照使用相同题集、语料、模型与指标口径；原始报告保留当时配置和数字，不随产品文档改写。

运行命令见 [README](../README.md)，设计与报告解读见 [评估检索质量](评估检索质量.md)。参数以各脚本 `--help` 为准。

## 在线问答指标与数据原型

离线召回脚本不调用模型，所以它测不出三件事：库外题是否真的被拒答、答案引用的是不是用户资料里的那一篇、句子是否越出了片段。拒答是否正确需要把实际判定结果与题目标注比较；脚本把人工逐题检查转为可复跑的流程。`scripts/eval_answers.py` 把它脚本化：

```python
EvaluationInput = {corpus_path, golden_sets[], embedding, top_k, faithfulness}
QuestionResult = {decision, status | failure, candidates[rank, source, score], expected_rank,
                  cited_ranks, cited_sources, wrong_source, first_text_ms, total_ms, stage_ms,
                  model_calls, generate_prompt_chars, supported, unsupported, uncited_sentences}
evaluate(input) -> {results[], summary{categories, sources, faithfulness, latency_ms, calls}}
```

- 样例语料在纯 ASCII 临时目录建隔离索引（B 的真实切片与 embedding），经 C 的真实判定/生成得到结果；只 import 各模块 `public`，不读业务 MySQL，不开业务 Chroma，不写历史。
- 指标：各类判定符合率（N 类 = 拒答正确率，Q/R 不符合 = 误拒，P 类 SUFFICIENT = 冒充完整）；**错源率** = 已作答且有引用的 Q/R 中引用片段全部不属于标注出处的比例——判定器与引用形态校验都抓不住它，需要进一步区分漏召回与生成选错来源；`--faithfulness` 用同一模型逐句核对"是否完全由所引片段支持"得到**引用支持率**，无引用句只计数；首段非空文本与完整耗时的中位数/最大值作为"端到端延迟"的唯一口径；模型调用次数与生成提示字符数逐题记录。
- 报告与同名 JSON（含候选与完整答案）写入 `docs/eval/`，命令行只记录相对路径。

| # | 裁决 | 理由 |
|---|---|---|
| D-1 | 拒答正确率、错源率、引用支持率只在线测，不在离线召回脚本里冒充 | 三者都依赖模型判断或生成结果；离线脚本"只展示召回不进分母"的口径保持不变 |
| D-2 | 错源率作为独立指标，且区分"标注出处未进候选"与"进了候选但没被引用" | Q21 型失败的答案引用合法、内容也未必编造，现有防线全部放行；两种成因对应检索与生成两个不同的改进点 |
| D-3 | 支持率核对用同一回答模型、逐句、二值输出；以冒号结尾的引导句和纯加粗标题不算句子，无引用句不核对 | 换更强的判官模型会把"判官能力"混进指标；逐句比整段更能定位越界；首跑发现"无引用句"里全是"特点如下："和加粗小标题，它们不是事实陈述 |
| D-4 | 报告记录本次样本数字，不把它当概率保证 | 模型输出每次运行可能不同；前后对照必须同一题集、同一策略、同一模型 |
| D-5 | 评估脚本自己节流：相邻模型调用停顿、上游不可用时冷却后整题重跑并记录重试次数；产品代码的"不自动重试"不变 | 首跑 42 题里 35 题在判定阶段 80 毫秒内被第三方接口拒绝——密集的逐句核对触发了限流，而 F 把一切失败都包成 `ModelUnavailable`；重跑只保留最后一次尝试的耗时，契约失败（如 INVALID_CITATIONS）不重试 |

不在本节内：评估数据库、网页看板、自动调参。

### 首跑基线解读（2026-09-21，纯稠密检索，报告 `eval/answers-baseline-2026-09-21.md`）

- 判定：Q 22/22、R 8/8 未误拒（其中 6 题判 PARTIAL，偏保守但仍作答）；N 类拒答 10/10——v2 的三道"主题在库、内容缺失"陷阱题（N8–N10）全部拒答；P 类 1/2，P2（PagedAttention 四行概要）被判 SUFFICIENT 冒充完整。
- 错源：Q21 标注出处未进候选，判定器看着 Redis 持久化片段判 SUFFICIENT，答案引用 [1][2][3] 全是 Redis——引用合法、判定合法、内容未编造，但答错了篇。它是 M4 混合检索的"前"数字（错源 1/30，标注出处进候选 29/30）。
- 引用支持率 86.9%（192/221，19 题各有 1–3 句）。对不支持最多的 5 题抽查（本机记录，不入库）后，不支持句分三类：把缩写展开成片段里没有的全称（Q12 的 LRU/LFU）、在片段基础上做推理性补充（R7 的"不一定能在到期瞬间全部清理掉"）、接近改写的复述（Q3）；没有发现编造事实。同一题两次运行的句子级结果差异明显（R2 一次 1/3、一次 7/0），支持率只能看总量趋势，不能逐题比较。
- 延迟：首段文本中位 2.6 s（最大 12.6 s），完整中位 6.6 s（最大 23.8 s），拒答 1.7 s；分段中位 embedding 0.94 s、判定 0.76 s、生成 5.8 s；生成提示中位 1846 字符。生成占八成以上，与 9-15 的测量一致。
- 判断：幻觉的主要入口在检索层（错源）而不是生成层（越界轻微且噪声大），优先级维持"混合检索 → 判定器标出相关片段/证据压缩"，后者以支持率总量不降、错源不升、生成耗时下降为门槛。
- 运行纪律：第一次全量因逐句核对密集调用触发第三方限流，35/42 题在判定阶段被拒（D-5 的由来）；带节流重跑 300 次调用、3 题各重试一次即成功。

### 混合检索前后对照（2026-09-22，B-17，报告 `eval/answers-hybrid-2026-09-22.md`）

同一 42 题、同一模型、同一语料，只把检索策略从 dense 换成 hybrid：

| 指标 | dense（9-21） | hybrid（9-22） |
|---|---|---|
| 标注出处进入候选（Q+R） | 29/30 | **30/30** |
| 错源率 | 1/30（Q21） | **0/30**：Q21 的答案核心机制引用 OS Buffer 片段 [4]，Redis 相关部分引用 Redis 片段 |
| 拒答正确率（N） | 10/10 | 10/10 |
| Q/R 误拒 | 0 | 0 |
| Q/R 判 PARTIAL | 6 | 8（Q7、R6 由 SUFFICIENT 变 PARTIAL，各重跑两次稳定；Q17 一次翻转属噪声） |
| P 类判 PARTIAL | 1/2 | 1/2 |
| 引用支持率 | 86.9%（192/221） | 85.7%（203/237），在同题跨运行的波动范围内 |
| 向量检索段中位 | 9 ms | 7 ms（最大 27 ms）——BM25 与融合没有可测的延迟代价 |
| 生成段中位 / 完整中位 | 5.8 s / 6.6 s | 7.8 s / 8.9 s，最大 191 s（R6 单次生成）——全部落在模型调用里，提示字符数 1846 → 1881 基本不变，属第三方接口当日波动，不归因于检索 |

判断：混合检索兑现了它的靶子（答错篇消失、v1 hit@1 补齐），代价是两题从"完整回答"降为"带边界声明的回答"；两者都是真实变化，一起写进 B-17。延迟结论只能靠检索段自身的毫秒数，模型段的差异需要同一时段的 A/B 才能比较，本轮不下结论。

### 判定器标出相关片段前后对照（2026-09-22，C-6，报告 `eval/answers-relevant-2026-09-22.md`）

同一 42 题、同一模型、同为 hybrid 检索，只把判定契约换成 `{"verdict", "relevant"}`：

中位数采用原始 JSON 的标准 median，展示值按报告取整；偶数样本取中间两值平均。

| 指标 | hybrid（C-6 前） | hybrid + relevant |
|---|---|---|
| 送入生成的候选 | 160/160 | **76/160（47.5%）**；32 题全部只送子集，选 1–4 个，中位 2–3 个；判定器 32 次全部输出了该字段 |
| 标注文档的片段被判定器全部排除 | — | 0 题 |
| 生成提示字符数中位数 | 1881 | **1096** |
| 生成调用中位数 | 7780 ms | **5013 ms** |
| 完整请求中位 | 8927 ms | 6116 ms |
| 首段文本中位 | 3505 ms | 3355 ms |
| 答案字符数中位 | 579 | 452 |
| 错源率 / 拒答正确率 / P 类 | 0/30 / 10/10 / 1/2 | 0/30 / 10/10 / 1/2 |
| Q/R 判 PARTIAL | 8 | 9（在跨运行波动内） |
| 引用支持率 | 85.7% | 87.3%（203/237 → 165/189，噪声内） |
| 判定调用中位 | 978 ms | 956 ms（多输出一个数组没有可测代价） |

解读：提示字符数是代码可归因的确定性变化；生成耗时的下降与之方向一致、幅度相当，但第三方接口的当日波动仍大（本轮 P2 一次首字等待 139 s 拉高了最大值），所以延迟结论写"报告中的生成调用中位数下降"，不写百分比承诺。样本质量指标基本持平，且没有整篇标注来源被筛除；这不证明每个必要片段都保留，仍需结合回答覆盖与引用支持率判断。判定器每次都输出了 `relevant`，缺失回退路径本轮没有触发。

### 难例集 v3 与真实失败问法（2026-09-22）

**难例来源**：`scripts/export_history_failures.py` 只读导出本机历史里 REFUSED / PARTIAL 的 10 条记录（3 条为已删除测试资料的残留），真实问法里出现了错别字（`checkpiont`）、缩写（`FDE`）、小写英文（`git`）——v1/v2 的"端正问法"测不到这些。标注表留在本机由人工填期望出处；据此写成 `eval/golden-set-v3-hard.md`（12 Q、3 R、4 P，每题标难点类型：精确术语、缩写、错别字、中英混用、专篇压制短卡、词法陷阱）。

**离线召回**（`eval/retrieval-v3-{dense,bm25,hybrid}-2026-09-22.md`）：

| 策略 | hit@1 | hit@5 | 漏召回 |
|---|---|---|---|
| dense | 13/15 | 15/15 | Q24（pdflush）第 2、Q31（Socket Buffer 短卡）第 3 |
| bm25 单独 | 14/15 | 15/15 | — |
| **hybrid（默认）** | **15/15** | **15/15** | — |

错别字题（`volumn`、`seesion`）两种通道都容错；两道"专篇压制短卡"在 hybrid 下都是第 1 名。**v3 的 Q/R 样本没有 top-5 漏召回，当前暂不启用有界改写重查**（C-2）。这些结果不代表对任意问法均无漏召回，也未覆盖全库统计或概览。

**在线评估**（hybrid + relevant，`eval/answers-v3-hybrid-2026-09-22.md`）：首轮把三道词法陷阱题标为库外（期望 NONE），结果三题全部判 PARTIAL，答案都明说"片段未提及、无法回答"并引用片段说明库里有什么，逐句核对无编造。对照 #15 的三态标准，这正是 PARTIAL 的定义（主题直接相关、主体缺失），NONE 留给"主题不在"（v2 N8 被判 NONE 即为证）。于是改标为部分覆盖类 P4–P6，并加上"不得编造缺失部分"的附加检验——评估口径跟着实测走，与 #15 当年单立部分覆盖类同理。纠正后的重跑数字见报告；首轮 JSON 保留在本机证据目录。

| # | 裁决 | 理由 |
|---|---|---|
| D-6 | 词法陷阱题按三态契约归为部分覆盖类，用支持率检验"不编造缺失部分"，不改判定器把它们逼成 NONE | 判定器的行为与 #15 的定义一致；把"主题在、内容缺"逼成拒答会把 P1–P3 这类真实部分覆盖一起误杀，用户也会失去"库里其实有相关内容"的提示 |
| D-7 | 带引用的元话语句（"以上回答基于片段""覆盖边界说明"）不送核对，单独计数；支持率保留判官误判的不确定性 | v3 重跑 16 条不支持句里 3 条是元话语句、2–3 条原文确有（R11"由类型注解自动推断"、Q31 Socket Buffer）、其余是改写或推理性补充；判官对元话语与改写偏严。排除元话语句是确定性规则；本次抽查显示判官偏保守，但未校准假阳性率，不能保证支持率是真实忠实度的下界 |

**纠正口径后的 v3 重跑结果**（hybrid + relevant）：Q 12/12、R 3/3 无误拒；错源 0/15；P 3/4（P3 这次判 SUFFICIENT，上一轮 PARTIAL——边界题的跨运行波动，两次都基于片段作答）；P4–P6 判 PARTIAL 且答案明说缺失、未编造版本号 / IndexedDB / Windows 用法；判定器 19 题全部标出子集（95 个候选送入 39 个）；支持率 79.2%（61/77，尚未排除元话语句），首字中位 3.2 s、完整 9.9 s。本轮报告生成于 D-7 之前，其支持率含元话语句；后续报告按新口径。

## 验证与适用边界

离线测试覆盖黄金集解析、排名计分、判定结果分类、引用与句子过滤规则、节流和报告生成。在线报告另外依赖真实 embedding 与回答模型，不能用离线测试代替在线质量结论。完整复现命令见 README。

当前题集主要检查局部正文问答，不证明全库数量、完整清单或全库概览的正确性。引用可定位也不证明统计对象正确；全局问题应另设数据源与覆盖验收。逐句支持率受模型判官的误判影响，保留原报告结果与样本口径，不给概率保证。
