# 问答工作流与边界

EasyRAG 当前使用固定工作流：一次混合检索后，先判断证据是否足够并选择相关片段，再生成或拒答，最后校验引用并保存历史。它没有自主选择工具、改写问题或发起第二轮检索。

本文面向首次了解项目的技术评审。阅读后应能说明为什么检索后还需要分步处理，并区分知识不足、模型判断错误与技术失败。召回设计见[检索链路与改进](检索链路与改进.md)，模块契约见[问答模块](子Issue-C-问答Agent.md)。

## 一、为什么一次检索之后还要分步

检索的 top-5 只是与问题可能相关的片段。相似度不能判断它们覆盖了问题主体，生成模型也可能在相关背景上补出资料没有的结论。因此，流程把“是否可以回答”和“如何表达回答”分成可观察的步骤。

```text
取得查询许可，冻结本次模型会话
  → 单轮混合检索，默认 top-5
  → 无候选：固定拒答
  → 有候选：三态判定 + relevant
      ├─ NONE：固定拒答
      ├─ PARTIAL：仅使用采用片段，明确缺失范围
      └─ SUFFICIENT：仅使用采用片段作答
  → 引用编号与出处均校验通过
  → 保存答案与来源快照
  → 正式成功响应或 SSE done
```

检索由 B 完成，C 负责判定、筛选、生成、引用和 trace；F 提供本次问题固定的模型会话，G 组织许可、出处补全和历史提交。判定与生成共用同一模型配置，但分别调用；中途修改模型配置不会替换正在回答的会话。职责划分见[架构设计](架构设计.md)。

一次问答当前只有一次 search。无候选不调用判定或生成；有候选且判为 NONE 时只调用判定；可以回答时通常是一次判定加一次生成。这些调用数指回答模型，不包括问题向量化，也不包括离线评估的逐句核对。

固定流程让分流、失败和提交时机可独立测试，也避免引入尚无实际任务支撑的工具规划。代价是判定增加调用与等待时间，且同一模型仍可能在两个阶段重复犯错；分步使错误可见，并不自动保证判断正确。

## 二、证据不足时有三种不同结果

| 判定 | 证据条件 | 返回行为 |
|---|---|---|
| `SUFFICIENT` | 与主题直接相关，足以支撑完整回答 | 生成，状态为 ANSWERED |
| `PARTIAL` | 有直接相关内容，但缺的是问题主体 | 基于已知内容生成，声明未覆盖范围，状态为 PARTIAL |
| `NONE` | 没有与主题直接相关的片段，词面相似不算 | 固定文案“知识库中没有找到能回答这个问题的内容。”，状态为 REFUSED |

PARTIAL 保留“库里已经有什么”的信息，同时要求指出无法回答的部分。如果把它一律拒绝，用户看不到已有相关资料；如果只要主题相近就直答，则容易把缺失主体补成确定结论。普通边角缺失也不应全部判 PARTIAL。

具体例子是 [v3 的 P4](eval/golden-set-v3-hard.md)：问题询问 pdflush 在哪个 Linux 内核版本被替代，现有资料只描述其定期刷盘的作用，没有版本信息。正确行为是说明已有机制描述和缺失的版本信息，不编出版本号；资料有这个术语不等于足以回答。

三态是模型判断，不是相似度阈值。既有 [relevant 在线报告](eval/answers-relevant-2026-09-22.md)中，10 道库外题全部拒答，但 2 道部分覆盖题仍有 1 道被判为 SUFFICIENT。这个错误说明仍须检查覆盖边界，不能将“有判定器”当作充分性保证。

## 三、检索到、采用和正文引用是三个集合

判定器在同一次结构化输出中返回状态与 `relevant`。后者是候选的原始 rank，表示进入生成上下文的片段；它不是 chunk ID，也不表示生成答案一定会引用这些片段。

例如以下编号关系：

```text
检索候选：rank 1 → chunk 101，rank 2 → chunk 205，rank 3 → chunk 309
判定输出：{"verdict":"PARTIAL", "relevant":[3, 1, 3]}
采用片段：[1] 与 [3]，按原候选顺序排列
正文引用：可以只出现 [3]
最终 trace：保留全部候选，relevant = [1, 3]
```

编号不会重新压成 `[1]`、`[2]`。返回的 sources 包含全部送入生成的片段，所以本例有 rank 1 和 3 的两个来源，即使正文只引了 `[3]`。前端按 trace 的原 rank 对齐来源，不能用 sources 数组下标解释引用。

检索过程按 `relevant` 显示“采用”“采用 · 正文引用 n”或“未进生成”。这些标签帮助判断证据在哪一步没有被使用，不表示答案语义已经验证。旧历史若未保存 relevant，会提示缺少采用情况，保留“正文引用 n / 检索结果”的显示；字段缺失不能当成显式空数组。

模型输出也有明确边界：

- SUFFICIENT/PARTIAL 明确给出 relevant 时，必须是非空、范围合法的整数数组；重复编号去重。
- 缺少 relevant 时沿用全部候选，保留对旧输出格式的兼容；因此不能假定每次都会压缩证据。
- 明确给出空数组、非法类型或越界编号是技术错误，不进入生成。
- NONE 不生成，trace 中 relevant 为空数组，不因模型附带的编号而改成作答。

### 为什么让判定器同时筛选

判定器已经阅读全部候选，让它同时指出支撑判断的片段，无须再增加一次模型调用。生成阶段因而减少无关上下文，也更容易核对哪些来源可用。代价是必要片段若被漏选，生成阶段无法补回。

同一 v1 + v2 题集的[全部候选对照](eval/answers-hybrid-2026-09-22.md)与[relevant 报告](eval/answers-relevant-2026-09-22.md)中，32 道已作答题的 160 个候选只送入 76 个；生成提示字符数中位数从 1,881 降至 1,096，生成调用中位数从 7,780 ms 降至 5,013 ms。中位数采用原报告口径，偶数样本取中间两值平均。

两次报告的错源率均为 0/30，没有出现标注来源进入候选后被整篇排除的题；这仍不能证明每个必要片段都保留。提示长度下降是直接变化，生成延迟受上游波动影响，不能据此承诺固定提速。逐句引用支持率分别为 85.7% 和 87.3%，也没有达到完全受支持。

## 四、生成后的校验保证什么

生成提示要求只依据采用片段作答，并在事实性结论后附 `[n]`。PARTIAL 额外要求说明库中未覆盖的范围。运行时引用校验要求答案至少有一个正文引用，且所有引用编号都属于采用集合。

单号、列表与范围都会解析。例如采用集合为 `{1, 3}` 时，`[1,3]` 合法，`[1-3]` 因展开后包含 2 而非法。代码、链接、图片、HTML 和转义文本中的数字不当作正文引用，前后端使用共同样例约束解析口径。

这道检查证明的是编号能够映射到允许的证据。它不逐句证明所有事实都有引用，也不验证句子是否由所引片段支持，更不能确认问题所指对象正确。逐句支持核对属于独立在线评估，模型判官自身可能双向误判；方法与限制见[评估检索质量](评估检索质量.md)。

| 失败 | 当前处理 | 为什么不能当拒答 |
|---|---|---|
| 检索或模型调用失败 | 返回技术错误，记录失败阶段 | 不知道是否有足够证据 |
| 判定结构无法解析、relevant 非法 | 不进入生成 | 没有取得有效分流结果 |
| 生成为空、无引用或含非法引用 | 不报告成功，不保存完成历史 | 答案没有满足输出契约 |
| 来源缺失或无法按 rank 对齐 | 要求恢复，不交付无出处答案 | 可能是数据与索引不一致 |
| 历史提交失败 | 不返回正式成功 | 尚未形成可回读的完成快照 |

业务拒答和 PARTIAL 都可以作为完成记录保存；技术失败不能伪装为“库里没有”。当前产品流程也不会自动重试来修复这些错误。

## 五、流式文本到达不等于回答完成

流式链路先补全并发送来源，再发送生成文本增量。前端在 `done` 前显示临时回答；完整文本通过引用校验、出处核对和历史保存后，才发出最终 `done`。已经显示的文字仍可能因为最终引用非法而失败，不能提前显示为已完成历史。

取消与历史提交按锁排序：提交开始前取消，不保存记录；如果已开始提交，即使客户端随后断开，也可能保存成功而没收到 `done`。前端因此不自动重试。正在执行的同步模型请求也不保证因取消立即中断，资源释放需要等待实际工作结束。

历史保存当时的答案、来源全文、模型摘要和 trace。资料更新或删除不重写这份证据；重新提问才检索当前资料。提交、断连和业务许可的具体契约见[应用编排](子Issue-G-应用编排.md)与[流式 API](api.md#流式问答)。

## 六、当前流程如何面对“一步答不好”

现有步骤能筛掉无关证据、显露覆盖不足、阻止非法引用被当成成功答案，并在成功响应前完成历史提交。它不能自动取得缺失资料，也不能修复没有进入候选的证据。知识不足时，用户可补充资料后重新提问；检索或模型出错时，按候选、relevant、正文引用、失败阶段和历史提交结果定位原因。

查询改写重查尚未实现。现有 v1/v2/v3 的 hybrid Q/R 均在 top-5 命中标注来源，因此没有已证实需要第二轮挽救的样本；这项决定及重新评估的条件见[检索链路与改进](检索链路与改进.md#五为什么目前不增加改写重查)。trace 可表达轮次，不表示当前已经执行多轮。

全库概览又是另一类问题：资料正文可能在描述别人的知识库，其数量不能作为当前系统统计。局部片段即使引用合法，回答对象仍可能错。当前问答没有接入数据库统计和完整目录，不能保证总数、完整清单或全库综述。

后续若研究受限工具编排，应先验证“查询资料记录”与“检索正文”各自能提供什么证据，再比较来源选择、正确性、调用数和延迟；拒答、引用、取消和历史提交约束仍需保留。V2 已延期，统计/目录上下文、分类树、工具自主调用和改写重查都不属于当前交付能力。
